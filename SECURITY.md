## 1b. PostgreSQL Runtime Hardening Findings (2026-11-08, v2.0.0)

| Finding ID | Severity | Risk Identified | Resolution & Verification | Status |
| :--- | :--- | :--- | :--- | :--- |
| **SEC-19** | **CRITICAL** | In-process idempotency mutex and in-memory campaign queue are unsafe on Cloud Run: multiple replicas and independent restarts could duplicate campaigns and notifications, and a crash lost all queued work. | Durable database-backed idempotency: `notification_campaigns.idempotency_key UNIQUE` + atomic `INSERT ... ON CONFLICT DO NOTHING` + sha256 payload hash (mismatch → `409 IDEMPOTENCY_PAYLOAD_MISMATCH`). Worker claims due campaigns with `FOR UPDATE SKIP LOCKED`; stale `processing` locks are reclaimed after 5 minutes. Verified by `PGT-07`/`PGT-09`/`PGT-10`/`PGT-11`. | **FIXED** |
| **SEC-20** | **HIGH** | express-rate-limit's default MemoryStore is per-instance; effective rate limits would multiply with each Cloud Run replica (abuse/DoS protection weakened under load). | `PostgresRateLimitStore` keeps counters in the `rate_limit_buckets` table with a single atomic UPSERT per hit, shared by all instances. Verified by `PGT-18`. | **FIXED** |
| **SEC-21** | **HIGH** | A production startup with an unreachable database would previously still serve traffic from memory, hiding data loss from operators. | Fail-closed startup: in PostgreSQL mode (default) the service exits with a sanitized `DatabaseUnavailableError` (no credentials logged) if the pool or migrations fail. `GOGO_IN_MEMORY_DEMO` is the only explicit escape hatch, documented as never-for-production. Verified by `PGT-03`. | **FIXED** |
| **SEC-22** | **MEDIUM** | Quiet hours were never enforced; timezone handling silently assumed UTC, so quiet-hour windows would fire at wrong local times. | `users.time_zone` (validated IANA) added via migration 002; quiet-hours evaluation runs per user timezone with overnight-window and DST-safe logic; users without a timezone get no quiet-hour enforcement (never a silent UTC assumption). Marketing campaigns only; `global_quiet_hours_enforced` config respected. Verified by `PGT-14`/`PGT-15`. | **FIXED** |
| **SEC-23** | **MEDIUM** | Delivery receipts lacked FK integrity and a uniqueness guarantee, so duplicate or orphaned receipts could inflate counts. | Migration 002 adds `UNIQUE (notification_id, device_id)` idempotent receipts plus FKs to campaigns/devices/users/apps; all delivery SQL is parameterized. Verified by `PGT-16`/`PGT-17`. | **FIXED** |
| **SEC-24** | **LOW** | Applied migrations could be edited silently, diverging live schema from the repository. | `schema_migrations` table with sha256 checksums; checksum mismatch aborts startup loudly. Verified by `PGT-01`/`PGT-02`. | **FIXED** |

Honest at-least-once disclosure: FCM delivery deduplication is durable (one campaign per idempotency key, one receipt per notification × device), but external FCM semantics cannot guarantee exactly-once delivery; a rare FCM-side duplicate after a network-level retry is possible and documented rather than hidden.

## 2. Defense-in-Depth Architecture

### 2.1 Identity & Authentication
- **Firebase ID Token + Revocation Verification**: Every protected backend route requires `Authorization: Bearer <Firebase_ID_Token>` verified via `adminAuth.verifyIdToken(token, true)`.
- **Zero Impact on Existing Flows**: Existing Google Sign-In, Email/Password login, password reset, guest mode, and Firestore game saves on `Arrow Out` and `Crystal Quest` remain untouched.

### 2.2 Role-Based Access Control (RBAC) & Data Isolation
- **`user` Role**: Can register/revoke only their own FCM device tokens (`userId === req.user.uid`) and read/update only their own per-app notification preferences (`prefId === ${uid}_${appId}`).
- **`admin` Role**: Verified server-side via `/admins/{uid}` and verified root admin email (`aaryapratik@gmail.com`). Required for broadcasting notifications, modifying app-level rate limits, reading documentation blueprints, and inspecting security audit logs.

### 2.3 Network, Rate Limiting & Input Hardening
- **Anti-Spoofing Rate Limiters**:
  - `standardApiLimiter`: 180 req/min/IP keyed by `extractTrustedClientIp(req)`.
  - `sensitiveMutationLimiter`: 30 req/min/IP on `/api/v1/auth/verify`, `/api/v1/notifications/send`, `/api/v1/apps`, `/api/v1/devices`, and `/api/v1/preferences`.
- **Strict Zod Schemas (`.strict()`)**: Rejects shadow/unknown fields (`unrecognized_keys`) and strips `<script>`, `javascript:`, and inline `on*=` event handlers.
